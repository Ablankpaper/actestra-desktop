# P6 Team Work Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver one durable, explainable, and controllable Actestra Team Work vertical capability that users can create, run, understand, and control through a real AionUI-native Team/group-chat experience across General and Goose workers.

**Architecture:** Actestra Core owns immutable run identities, admitted plans, run snapshots, revision history, budgets, dependencies, attempts, approvals, artifact references, cancellation, and recovery. Electron main hosts a scheduler over narrow General/Goose worker ports and a separately supervised planner-sidecar port; sidecar output is always re-admitted before persistence or execution. A fixed preload/main provider owns the native AionUI `/api/teams` boundary.

AionUI v2.1.41 remains the sole product surface, design language, component system, and navigation foundation, but its Team pages and information architecture are not frozen. Downstream patch 0014 may add or adapt AionUI-native Team list, `/team/:id`, group-chat, status cards, controls, guidance, and Actestra-specific explanations under recorded R1/R2 retention, compatibility, and rollback evidence. It must not import or expose a Goose or Eigent application UI.

**Tech Stack:** TypeScript, Electron main/preload, Node.js supervised child processes, SQLite `node:sqlite`, Vitest, the existing General Worker and Goose ACP journey services, AionUI v2.1.41 downstream overlays, and a versioned JSON-lines planner-sidecar protocol.
